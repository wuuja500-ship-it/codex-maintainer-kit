# 30-Day Maintenance Plan

This plan helps the repository look and behave like a real maintained open-source project.

## Week 1

- Publish the repository publicly on GitHub.
- Create the first release: `v0.1.0`.
- Open the first roadmap issues from `GITHUB_SETUP.md`.
- Add screenshots or terminal output examples to the README.
- Ask 2-3 developer friends to try the CLI.

## Week 2

- Add `maintainer-kit.config.json` support for custom label rules.
- Add tests for custom label rules.
- Add a README example showing a real configuration file.
- Close the matching roadmap issue with a linked pull request.

## Week 3

- Add GitHub API reading for issues and pull requests.
- Document required GitHub token permissions.
- Add a dry-run mode so maintainers can preview comments before posting them.

## Week 4

- Add GitHub release draft output.
- Publish `v0.2.0`.
- Update the Codex for Open Source application with real repo activity.
- Apply after the repository has visible commits, issues, and releases.

## Important

Do not fake stars, users, downloads, or maintainer activity. A small real project is stronger than a fake-looking project with inflated claims.
